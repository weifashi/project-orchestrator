# 编排画布与实时运行画布设计

## 目标

把当前以表单和列表编辑的流程模板，改成类似 n8n 的节点画布；把当前以表格查看的任务运行记录，改成与模板同形的只读实时画布。

## 已确认的产品边界

```text
Web 负责：编辑未来流程模板、查看任务运行。
Codex / Claude 负责：创建任务、确认、暂停、恢复、重试、部署。

保留：本机 SQLite、常驻服务、MCP、Codex/Claude Adapter、版本快照、审计。
不做：Web 运行控制、任意脚本节点、多人协同、运行中迁移流程。
```

## 用户体验

### 1. 编排画布

进入“流程模板”后，主区域是可缩放和拖动的画布：

```text
左侧角色库 → 中间流程图 → 右侧节点设置
```

- 角色库提供已发布且可用于未来任务的内置角色。
- 拖入角色创建阶段；也可点击左侧角色卡上的“＋”快捷添加。选中某节点时，快捷添加的角色自动插入并连接在该节点之后；没有选中节点时，角色放到画布右侧并提示用户选择前置节点。
- 每个普通节点下方有“＋”快捷入口，点击后打开小型角色选择器；选择角色即创建节点并自动连线。
- 一个节点多条出边代表可并行的后续阶段；多个入边代表必须等待所有前置阶段完成。
- 选中节点时右侧显示角色、是否可选、会话确认点、失败策略和返工组；JSON、Schema、版本 ID 收进“高级设置”。
- 节点移动只改变画面位置；“自动排版”能用无环依赖关系重新排成从左到右的布局。
- 保存写草稿，发布创建不可变版本。发布前显示画布定位的错误，而不是后端错误码。

### 2. 实时运行画布

进入“任务记录”后，主区域展示任务创建时冻结的流程版本：

- 节点以 `queued / ready / running / waiting_for_user / succeeded / failed / skipped / interrupted` 映射为易懂的中文或英文状态、图标和颜色。
- SSE 事件到达后只更新对应节点、进度和右侧详情，不重置用户的缩放、位置和已选节点。
- 活跃连线有动画；已成功路径用完成颜色；失败路径用红色。
- 点击节点只显示人话：正在做什么、已产出、失败原因、下一步、相关产物和最近事件。
- 运行画布没有开始、暂停、恢复、取消、跳过、重试、批准、拒绝或部署按钮。
- 等待确认、可重试失败、未知副作用保留现有提示，但措辞改为“回到发起此任务的 Codex / Claude 会话处理”。

## 技术设计

### UI 基础能力

使用 MIT 开源 `@xyflow/react` 仅承担画布的拖放、连线、缩放、选择、键盘操作、小地图和受控节点状态；业务规则、版本发布和运行状态仍由本项目自研。

```text
WorkflowVersionEnvelope
├─ stages                    执行语义：阶段和角色版本
├─ edges                     执行语义：依赖关系
├─ iteration_groups          执行语义：返工规则
└─ canvas (新增，可选)       展示语义：节点位置、视口
```

`canvas` 不参与调度决策。它随草稿保存、随发布版本冻结，因此历史任务能按原图回放；缺少 `canvas` 的旧版本首次打开时由前端自动布局，用户保存后才写入位置。

### 发布校验与画布反馈

现有服务端发布校验仍是最终裁决。前端增加同构的预检查以即时标记：

```text
无入口节点                  → 节点红框
不可达节点                  → 节点红框
循环依赖                    → 涉及的边红色
强制安全门被绕过            → 危险目标节点及缺失边红色
iteration_group 引用错误    → 节点和返工组红色
```

前端预检查绝不替代服务端校验；发布请求仍交由 `ConfigService.publishWorkflow`。

### 实时状态投影

运行图不新增执行控制 API。它复用：

```text
GET /api/read/runs/:id                 Run、StageRun、Attempt、产物、确认、事件
GET /api/read/workflow-versions/:id    冻结工作流图
GET /api/stream/events?run_id=:id      实时事件
```

前端通过 stage key 聚合每次 iteration 的 StageRun：同一阶段若有多轮，画布节点显示最新一轮状态，侧栏保留全部轮次。状态优先级是 `failed > waiting_for_user > running > ready > queued > succeeded/skipped`，终态 Run 会覆盖未活动的节点颜色。

## 数据与接口变更

| 位置 | 变更 | 目的 |
|---|---|---|
| `packages/contracts/src/workflow.ts` | 在 workflow version data 增加可选 `canvas` | 版本化节点坐标和视口 |
| `apps/web-console/src/api/types.ts` | 增加画布、节点和运行投影类型 | 防止把内部数据库行直接传进 UI |
| `apps/web-console/src/api/client.ts` | 增加明确的 `workflows.getVersion()` | 读取运行冻结版本 |
| `apps/web-console/src/workflow/*` | 新的图转换、布局、校验和 canvas 组件 | 分离业务图逻辑与 React 视图 |
| `apps/web-console/src/pages/workflow-editor.tsx` | 用编排画布替换当前表单编辑器 | 用户编辑体验 |
| `apps/web-console/src/pages/run-detail.tsx` | 用实时运行画布替换当前详情主视图 | n8n 式运行观察 |

不新增数据库表；canvas 作为不可变工作流版本内容的一部分保存在已有 CAS 与草稿 envelope 中。无现有业务表字段删除或改名。

## 安全和权限

- Web API 仍只允许 `/api/config/*` 模板/角色写入和 `/api/read/*` 只读访问。
- canvas 发布按钮只发布未来模板，不创建 Run。
- 必须在 UI、HTTP 路由测试和端到端测试中断言运行控制 API 不存在。
- 画布不展示 adapter credential、lease、内部 token、CAS object ID 或未脱敏日志。

## 验收标准

1. 用户可以在画布拖入已有角色，或用左侧角色卡“＋”及节点下方“＋”快捷添加角色；随后连接阶段、保存草稿、自动排版和发布合法模板。
2. 用户一眼能看出串行、并行、安全门、确认点、失败返工关系，不需要理解内部字段名。
3. 非法连线与缺少必经安全门在发布前和服务端发布时均被拒绝并定位。
4. 打开旧模板仍可显示自动布局；保存后布局在重新打开时保持。
5. 运行详情显示与 frozen workflow version 对应的图；SSE 状态改变后节点实时更新。
6. Run 详情页没有任何运行控制按钮或运行控制 HTTP 请求。
7. 中英文切换覆盖节点名称、状态、按钮和侧栏说明；用户自由填写内容保持原文。
8. keyboard 可以选中节点、移动焦点并读取节点状态；缩放和小地图不造成横向溢出。

## 非目标

- 不做 n8n 的任意代码节点、HTTP 节点、定时器、Webhook、队列或集成市场。
- 不做多人同时编辑、评论、光标协作。
- 不做运行图上的直接重试、确认或部署。
