# n8n 风格画布与主题设计

## 目标

让流程模板和运行观察首先呈现为稳定、可定位、可阅读的画布；视觉语言对齐 n8n 暗色编辑器，但不复制其“网页执行工作流”能力。

## 已确认事实

- `feature-development` 的已发布模板在本机 SQLite/CAS 中含 9 个阶段和 12 条边，数据不是空的。
- 现有浏览器自动化能渲染节点；实际页面的空白由 React Flow 在容器最终尺寸稳定前进行首次定位、未再次适应画布导致。

## 交互与状态

```text
打开流程
  ├─ 有已保存视角 → 恢复该视角
  ├─ 无已保存视角 → 容器稳定后自动适应所有节点
  ├─ 节点不可见/画布尺寸变化 → 再次适应一次，不写入草稿
  └─ 阶段为 0 → 居中显示“添加第一个节点”空状态

用户手动平移 / 缩放
  └─ 只在真实用户交互结束后保存视角
```

## 视觉规则

- 画布使用 n8n 风格的石墨灰/深灰，而不是大面积蓝黑渐变；网格更细、对比更低。
- 主操作使用暖橙色；危险与状态仍保持语义色：安全门金色、成功绿色、失败红色、运行蓝色。
- 顶部只保留名称、保存状态、保存/发布等少量动作；工具条贴画布左上，缩放/小地图贴画布右下。
- 节点使用浅深灰卡片、圆形角色标记、清晰的输入/输出端口；选中态只用一圈高对比边框。
- 角色市场与节点设置均为可关闭抽屉，不永久压缩画布。
- 运行画布复用相同样式，但只读；不得出现网页执行、暂停、重试、确认或部署入口。

## 验收

1. 已有阶段的流程首次打开后在 1 秒内可见至少一个节点；点击“适应画布”可再次恢复全图。
2. 无阶段的模板显示空状态和“添加第一个节点”。
3. 所有 390px、768px、1280px、1568px 页面无横向溢出。
4. 中英文模式下按钮、状态、诊断和画布辅助文案均对应当前界面语言；用户写入的业务正文不被翻译。
5. Web 仍无 Run 控制 API 或按钮。
