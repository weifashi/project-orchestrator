# n8n 式编排与运行画布交互设计

## 决策

用户确认同时实施两层能力：

```text
1. n8n 式核心画布交互
2. 节点市场、搜索、分组、子流程入口等扩展能力
```

目标不是让控制台变成通用自动化平台。它仍只编排本项目的角色 Skill，网页仍不能创建、控制、确认或部署任何 Run。

## 当前问题

现有流程编辑页把标题、版本提示、角色库、画布和属性面板同时固定展示。画布被挤在中间，节点拖动、连线和定位需要频繁滚动；右侧面板在未选中节点时仍占空间；左侧角色库长列表没有搜索、分类或快捷操作。

## 目标体验

```text
进入流程模板
  → 主区直接是无限画布
  → 空白处拖动平移；滚轮缩放；右下角小地图定位
  → 从「添加」或节点 + 打开角色选择器
  → 拖角色到画布创建节点；从端口拖线建立依赖
  → 单击节点才显示右侧属性抽屉；空白处或 Esc 收起
  → 保存草稿 / 发布新版本；运行中与历史 Run 不受影响
```

### 画布优先布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 模板名 · 草稿状态     撤销 重做 | 自动排版 适应画布 | 保存草稿 发布 │
├──────────────────────────────────────────────────────────────────────┤
│                                                                     │
│                        无限编排画布                                │
│      节点拖放 · 框选 · 连线 · 平移 · 缩放 · 小地图                 │
│                                                                     │
│ [添加节点] 浮动按钮                         缩放 / 适应 / 小地图   │
└──────────────────────────────────────────────────────────────────────┘
             ↑                                  ↑
        角色库抽屉                          属性抽屉
        按需打开                              选中节点才打开
```

固定页头只保留模板名称、未保存提示和主要动作。版本说明改成可收起的轻提示，不占用首屏。默认不展示左右面板，让画布占用全部内容宽度。

## 交互规格

### 节点添加与连接

| 用户动作 | 结果 |
|---|---|
| 点击画布浮动「添加节点」 | 打开可搜索的角色选择器，选择后在当前视野中心创建节点 |
| 从角色库拖卡片到画布 | 在落点创建节点 |
| 点击节点上的「＋」 | 打开快速角色菜单；选择后插入该节点后方并自动连线 |
| 从来源节点右端口拖到目标节点左端口 | 创建 `requires` 依赖边 |
| 点击边 | 显示边的依赖说明；可删除普通边 |
| 拖动节点 | 仅保存展示位置，不改变执行语义 |
| 框选 / Shift 多选 | 批量移动、批量删除普通节点或建立分组 |

安全门、强制依赖和返工规则保留平台校验：它们可查看、可定位、不能被删除或绕过。画布在用户尝试非法连接时即时解释原因，发布时继续由服务端作最终校验。

### n8n 式导航与快捷键

```text
空白处拖动                 平移画布
滚轮 / 触控板               缩放画布
F                           适应所有节点
Ctrl/Cmd + Z / Shift + Z     撤销 / 重做本次草稿编辑
Delete / Backspace           删除选中普通节点或普通边
Esc                          取消连线、清空选择、收起抽屉
Ctrl/Cmd + S                 保存草稿
```

每个拖拽能力都有替代操作：角色选择器可键盘搜索并回车添加；节点和边可通过键盘焦点选择；删除、连线与属性修改均有可见控件。画布不因拖拽成为唯一操作路径。

### 节点市场与分组

角色库由常驻长列表改为「添加节点」抽屉：

```text
搜索角色 / 筛选：全部、调查、设计、开发、质量、安全、交付、记忆
├─ 最近使用
├─ 内置角色
└─ 当前项目自定义角色
```

首版不接第三方 Skill 市场。节点市场仅检索本机已发布、可用于未来 Run 的角色版本。节点组是展示分组（例如“设计”“质量门”），保存为画布元数据，不改变调度顺序；组内节点依然由边决定依赖。

「子流程」只作为可折叠的命名画布组与跳转入口：用户可把一组阶段收起为一个摘要节点，双击进入该组查看内部图。发布时展开为原有阶段和边，不新增运行时子工作流、跨模板调用或新的调度语义。

### 属性抽屉

单击节点后，右侧以覆盖式抽屉显示，不压缩画布：

```text
常用：名称、角色、失败策略、最大尝试次数、可选、会话确认
高级：输入/输出契约、版本、返工组、调试信息
```

属性抽屉窄屏时全屏覆盖；关闭后还原焦点到原节点。未选中节点时不显示“请选择一个角色”的大块空状态。

## 实时运行画布

任务记录页沿用相同画布导航：全屏画布、适应、缩放、小地图、节点详情抽屉和实时 SSE 更新。它是只读模式：没有添加、删除、连线、保存、发布、运行控制或确认按钮。

运行中的节点使用状态、图标、文字和边线共同表达，不只靠颜色。执行日志、产物、失败原因和“下一步请回 Codex / Claude”的说明收进节点详情抽屉；默认视图只呈现当前路径、等待项和失败项。用户可切换“全部节点”查看完整流程。

## 实现边界

```text
采用：@xyflow/react（MIT）处理画布手势、拖放、连接、小地图、选择。
自研：角色选择、撤销栈、组/子流程展示、流程规则、发布校验、运行状态投影。
不做：任意脚本节点、Webhook、定时器、队列、第三方节点市场、多人协作。
```

现有 `canvas` 数据继续只存展示信息。新增可选画布元数据用于 viewport、节点组和折叠状态；它不影响 workflow stages、edges、iteration groups 或任何执行决策。旧版本缺少元数据时仍自动排版。

不新增数据库表；版本内容继续存入已有草稿 envelope / 已发布 immutable envelope / CAS。Run 继续绑定创建时的 workflow snapshot，历史画布不可被后续模板编辑修改。

## 验收标准

1. 编辑页首屏中画布在 1440px 宽桌面上占主要内容宽度；左右抽屉关闭时不挤压画布。
2. 用户可拖入、搜索添加、节点 + 添加、连接、框选、多选、删除、平移、缩放、小地图、适应与自动排版；所有动作响应流畅且无横向页面滚动。
3. Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl/Cmd+S、F、Esc、Delete/Backspace 有明确、可测试的编辑语义；输入框获得焦点时不劫持文字编辑快捷键。
4. 角色抽屉可搜索、分类和展示最近使用；它只列 active 且有 current version 的本机角色。
5. 节点属性仅在选择节点时以抽屉呈现；节点组可创建、折叠、展开和改名；子流程摘要可进入/返回，且不改变发布后的执行 DAG。
6. 强制安全门和规则依赖不能借由拖拽、删除、多选、分组或子流程绕过；非法操作在界面解释，发布仍由服务端拒绝。
7. 实时运行画布复用画布导航、SSE 局部更新和只读详情抽屉；Web 不出现运行控制按钮或控制 API。
8. 简体中文和 English 覆盖新增界面文案；角色名和用户填写内容保持原文。
9. 覆盖画布图转换、快捷键、添加/删除/连线、抽屉、组折叠、旧数据兼容、只读运行图和端到端发布快照；通过 lint、typecheck、unit、integration、E2E、build、diff-check。

## 风险与处理

| 风险 | 处理 |
|---|---|
| 大图拖动卡顿 | 使用受控最小更新；拖动期间只更新本地位置，结束后合并写入草稿；SSE 只更新受影响节点 |
| 复杂交互误删 | 删除前只对普通节点/边生效；安全门禁用删除；撤销栈支持恢复 |
| 画布信息过载 | 默认聚焦当前选择/当前运行路径；侧栏和高级信息按需打开 |
| 组与真实依赖混淆 | 组只做视觉边界，边和端口始终展示真实依赖关系 |
